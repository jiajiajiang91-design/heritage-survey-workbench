# 外壳与令牌 · 规格

把工作台的令牌层与外壳换成产品原型 v4 的取值与结构：令牌由 50 个换成 v4 设计系统的一套，页面样式里 631 处字面 px 改为令牌引用，导航由十三视图平铺改为八阶段两层，项目级页面移到顶栏。

## 一、依据

- 需求：核心 PRD 功能 F03 项目列表、附录 A.4 的界面用词口径（状态词一律取代码的标签表取值）
- 界面结构：`../../01_产品/03_界面与交互形态.md` 第二节图 1 的三栏线框、第三节表 2 的十一个工作区视图与表 3 的三个项目级页面
- 视觉取值：Figma 文件 `JjPzJEu3boS7xFFlERfs3B` 的四个变量集合共 148 个变量，定义在页面 `01 基础规范` 与 `02 组件`；逐项取值见 `../../05_验证证据/14_界面重做/设计参数取值表.md`
- 阶段与视图的对应：`../../05_验证证据/14_界面重做/缺口与疑点裁决记录.md` 第三节第 7 条的八阶段对应表，第六节第 1 条的阶段 08 页签名更正
- 偏离与已定口径：同目录 `v4对v3的偏离清单.md` 全文
- 现状测量：`tokens.css` 50 个变量；`styles.css` 395 行含 585 处字面 px；`components.css` 266 行含 46 处字面 px；`visual-spec.test.ts` 只挡字面色值与 12px 字号下限

## 二、用户故事

作为测绘人员，我按八个阶段推进一栋建筑的成果，每个阶段只看见这一步该看的视图，以便于不在十三个平铺视图里找当前该做什么。

作为复核人员，我在顶栏直接进项目列表、模型运行与用量、修改历史三个跨项目页面，以便于不必先进某个项目才能看到跨项目信息。

## 四、业务规则

**取值只有两个来源：Figma 变量，或原型节点上量到的值。** 两者都取不到的，列为缺口报出来，不在实现里就近取一个像的档位。`styles.css` 现有的 585 处字面 px 正是这么积累出来的，其中大量间距不在任何一档内。

**界面上的状态词一律取代码的标签表取值。** 来源、审核状态、数据状态、解析状态、问题类型五张表是唯一出处，见核心 PRD 附录 A.4。改外壳时不得引入表外的词。

**改名只改显示层。** 视图命名统一到界面文档表 2，改的是 stages 的 label，stage id 不动。id 出现在助手动作的 payload、路由与测试里，改 id 会牵动动作层。

**一个阶段独占自己的视图。** 不出现两个阶段共用一组页签的情形，理由见裁决记录第三节第 7 条。

## 五、界面要求

- 左栏显示八个阶段，各带序号、名称与该阶段自己的数据情况；三态为当前、已完成、未开始，当前阶段高亮
- 第三态由未到改为未开始（2026-08-22 第四组实测后改）。原写法暗示按序推进，实测对不上：高都演示包里记录现状没有数据，而它后面的生成图纸有 12 项产物、检查签发已检查。本产品允许资料先到现状后补，把后面的阶段显示成未到会误报状态。判据改为只看该阶段自己有没有数据
- 三态不能只靠点的颜色区分，每行带一句读屏可取的文字（视觉规范第 7 节）
- 中栏在阶段含多个视图时显示页签行，页签名与界面文档表 2 一致
- 顶栏右侧三个项目级入口；进入后不显示左栏与助手栏
- 窄屏按第三节的断点收起，收起助手栏后顶栏出现唤起图标
- 焦点样式为 2px 主操作色外框，不移除默认焦点

## 六、不做

- **不改十九屏的内容与数据。** 本单元只动外壳、令牌与样式，屏内内容按现状保留，逐屏实现是单元 08 的范围。
- **不做暗色模式。** `Semantic Color` 只有 Light 一个模式，集合已是别名结构，将来加 Dark 只需改 Semantic 层指向。理由见缺口清单第三节第 3 条。
- **不做来源标记的形状变体。** 口径已改为颜色加文字标签，见裁决记录第七节第 3 条。
- **不补影响范围能力。** 属单元 07。
- **不改 stage id 与助手动作层。** 只改显示名。
