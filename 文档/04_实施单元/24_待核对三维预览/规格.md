# 待核对三维预览 · 规格 v1.0

本单元让已有依据且参数完整的待核对对象可先预览，再核对采用。

## 一、依据

本单元落实核心 PRD 第 3.1、3.3、4.5 节及 F07，接续单元 19、21、23。

课堂要求为先呈现结果再核对，见辅导 13 39:54 至 44:43。第一用户、任务目标和成果资格沿用现行定义。

## 二、用户故事

成果编制人员可以先查看有依据的局部对象，与原件和候选尺寸对照，修正后采用用于制作。

## 三、范围与规则

预览只表达来源与参数支持的部分。

| 项目 | 规则 |
|---|---|
| 支持对象 | 沿用长方体、圆柱和轮廓挤出，不新增建筑自动重建能力 |
| 参数来源 | 可读候选中明确的有效长度、已有人工参数及明确位置依据；每个参数保留来源 |
| 几何条件 | 形体所需参数完整且位置有依据才显示；缺项对象仍列出具体字段和原图位置 |
| 待核对状态 | 预览和对象标记待核对，展示原值与来源；不自动写采用事实，不计模型制作完成 |
| 修正采用 | 用户核对尺寸、类型与位置后经已有命令保存，再进入核对后模型生成 |
| 更新 | 参数或资料变化使旧预览过时，可重新生成；采用后的稳定身份与原件定位保持 |
| 文件资格 | 待核对预览不能进入当前成果、检查签发或交付集合；正式成果仍采用已核对数据 |

现有构件识别仅提供名称、类别、二维区域，不提供三维参数。二维框不能当作三维坐标，长度不能由相对标高替代。现有内部参数只验证交互，不能作为真实建筑依据。

## 四、工程与界面约束

实施前先确定预览数据与核对后规格的边界，再开发界面。

预览入口置于构件参数编辑页，原件保持可见，显示对象、缺项及核对动作。编辑中网格使用既有 Three.js；核对后模型继续由 CAD 生成。项目事实仍经命令服务写入；预览不构造 GeometryRevision，异步完成须核对当前资料和参数，失败保留原件与修正内容。

候选长度进入预览不会自动采用。用户点击“核对并保存构件输入”后，尺寸采用与构件输入通过同一 CommitFacts 一次提交；修正值必须提供说明。相对标高、拒绝条目或无有效正数值的候选不能作长度。类型尚未确定的候选只在用户明确选择该长度字段后预览，采用时明确保存为长度。

材料为可补充属性，未提供时记录未知与缺项，禁止填入推断材料。未保存形体只保留在编辑会话；取消、离开编辑或刷新时清除。已保存输入随项目包恢复，重新打开可再次预览。技术规则见架构第 1.6 节，界面规则见界面文档第 6.1 节。

## 五、不做

本单元不扩大输入能力或工程资格。

不根据照片猜测隐藏尺寸、三维位置和材料；真实识别与 T-DL-03 按独立条件验证，完整建筑制作和外部软件交换另验收。
