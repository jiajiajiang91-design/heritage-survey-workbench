# 原始图纸处理 · 规格 v1.0

本单元使原始资料形成明确的逐文件处理结果，并接入 TIFF 原件的无损 PNG 派生图。

## 一、依据

本单元落实核心 PRD v5.0 的 F02 和第 3.4、3.5、4.5 节，接续单元 17。

技术架构第 0、1.4、7.2 节约束命令写入、原件保留及模型输入。T-DL-01 的三份 TIFF 已有本机无损转换探查，来源见证据 23；探查只证明像素保持，未证明识别准确。

## 二、范围与规则

处理结果按资料分别记录，成功、失败和未支持均保留原件。

| 项 | 规则 |
|---|---|
| TIFF | 本机 Python 与已有 Pillow 解码单帧 TIFF，生成 PNG；不缩放、不裁切、不转色，尺寸、模式和像素哈希复核一致才成功 |
| 关联 | 原资产编号和哈希保持；派生资产另存，记录原图与派生图尺寸、原像素哈希、恒等坐标映射；候选仍引用原资料编号 |
| 格式范围 | 支持 PNG 能保持模式的单帧 TIFF；多帧、模式无法保持、超过 1.5 亿像素明确未支持。损坏文件显示失败，可重试 |
| 可读结果 | 有效非空文字、12 MiB 内可解码 JPEG、PNG、WebP、12 MiB 内成功 TIFF 派生图可用于提取；扫描 PDF 无文字层和其他格式显示未支持及原因，不按文件名判断内容覆盖 |
| 混合文件 | 保存及处理逐份继续，显示正在处理与具体结果；单份失败不撤销原件或其他成功项 |
| 重试 | 在同一资料上追加处理结果，不另建资料；最新结果用于输入和显示，失败不宣称可读 |
| 预览与下载 | 显示派生图身份和尺寸；归一化图上位置不变；下载仍取原件 |
| 模型输入 | 接入可用派生图，记录原哈希与实际图像哈希；所选资料有不可用项时在调用前列明，用户可用可读项继续；不得静默漏项 |

可读只表示当前程序能够提供图像或文字输入，不表示已确认尺寸、对象或完整建筑。预览核对流程与完整案例在后续单元验收。

## 三、数据与工程

新增可选图像派生关联和读取能力字段，旧项目包仍可读取。

派生图、处理结果经 ProjectCommandService 提交，浏览器仍为本地项目真源。服务端只做解码并返回结果，不写项目；沿用会话及来源校验。转换失败追加失败记录并保存原件。普通图像用浏览器解码检查；重试时读取原件。服务端处理不调用外部模型。

## 四、不做

本单元不将格式转换当作模型识别通过。

不改写 T-DL-01 原失败记录，不补造楼层、开口或构造；不实现扫描 PDF OCR、多帧 TIFF 拆页或坐标重采样，不执行真实模型请求，不更新演示包。
