# 设计参数补全与原型对齐 · 计划

## 目标

把 v3 的六类设计参数取全，把内容换成代码里的真实数据后在 Figma 建 v4。不改代码。

## 任务组

### 第一组　取全设计参数

1. 逐屏查变量定义，合并去重，得到 v3 用到的全部变量。
2. 变量取不到的项，读节点属性：字号、字重、行高、圆角、内边距、控件高度、边框宽度。
3. 两者都取不到的从截图量取，量取值单独标注，不与变量值混列。
4. 确定主操作黑色的准确色值。
5. 确定来源标记五类的色值与五种形状的画法参数。
6. 产出参数取值表，每项含：类别、名称、取值、来源方式、来源节点。
7. 缺口单独成表，写明缺什么、为什么取不到、建议怎么定。

验证：六类参数逐类核对，v1.0 有而 v3 没有的项全部出现在缺口表里，无一遗漏也无一被推测值填补。

### 第二组　真实内容盘点

1. 从三个演示项目的项目包里取出真实数据：项目名、建筑对象名、资料文件名与份数、构件数与待确认数、事实条数、成果数、检查结果、交付状态。
2. 取当前代码里的真实文案：阶段名、视图名、按钮文字、状态标签、空状态说明。
3. 确定 v4 每一屏用哪个演示项目作为示例内容，理由写明。
4. 产出内容对照表：v3 的示意内容、对应的真实内容、真实内容的出处。

验证：v4 要用到的每一项内容都能指出代码或演示数据里的出处。

### 第三组　疑点裁决

把勘察记录里的七处疑点整理成具体问题交 JIAJIA：

1. 助手栏进度分母 7 与左栏八阶段不一致，以哪个为准。
2. 顶栏面包屑与左栏对象名两种写法，统一成哪个。
3. P01 两个新建入口是否同一动作。
4. 用户消息气泡与主按钮同为黑底白字，是否要区分。
5. P01 指标区的待确认数与可导出成果数，数据从哪里来。
6. 本次范围是整段文本还是结构化字段。
7. 阶段与页签多对多是有意设计还是画的时候没统一。

裁决结果记录后才进 v4。

验证：七条逐条有裁决，无一悬空。

## 风险

**字阶可能取不到。** 若 v3 的字号直接写在文字图层而非变量，变量查询取不出来，要逐个文字节点读属性。第一组第二步就会知道是哪种情况。取不到就列缺口，不用 v1.0 的六档顶替。

**建 v4 需要 Figma 写权限。** 写入 Figma 属对外动作，且会在 JIAJIA 的文件里新增页面。第四组执行前先确认。若写权限不可用，退回方案是产出一份逐屏内容替换说明，由 JIAJIA 在 Figma 里手动改。

**内容变长会破版。** 真实项目名与文件名可能比原型的示意内容长很多，例如演示项目里的资料标题是 HABS 实测图第 16 张：首层平面与二层平面，比原型的 IMG_0334.jpg 长数倍。放不下时不新造样式，按已有规则处理并记录，处理不了的记为缺口。
