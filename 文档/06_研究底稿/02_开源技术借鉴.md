# 02 · 开源技术借鉴 v2.0

## 1. 结论

现阶段以已接入的工程能力和制作缺口为依据，不沿用早期“动作层不存在”等过期判断。

2026-08 的研究曾参考 deepseek-harness、ACA-Builder 等项目。外部设计是否可借鉴与本产品是否已经实现分别判定。当前动作、规则、词表及几何能力以本地源码为准，不能用数据结构复杂度比较产品优劣。

## 2. 当前可检查的采用结果

已有工程能力支持继续补齐制作输入，无须为记录管理重建基础架构。

**表 1：技术能力与本地证据**

| 能力 | 可检查的代码 | 当前结论 |
|---|---|---|
| 受控动作目录 | `packages/domain/src/assistant-action-delivery.ts`、`apps/server/src/actions/action-catalog.ts` | 登记表含 14 个可执行动作；另 7 个仅在界面文档占位，未登记为可执行 |
| 参数校验与执行 | `apps/server/src/actions/assistant-routes.ts` | 模型输出与实际执行分层，错误行为按界面契约检查 |
| 类型化几何 | `packages/domain/src/geometry.ts` | 明确的长度、角度与构件关系供生成器处理，不证明自动识别可靠 |
| 来源与影响 | `packages/domain/src/provenance.ts`、`packages/application/src/impact-service.ts` | 具备来源和影响查询，任务与形制引用仍存在已知缺口 |
| 制作写入 | `apps/workbench/src/workbench/useRecordWrites.ts` | 图幅、视图与构件输入仍有 JSON，需转为普通表单与候选复用 |

“可执行”只表示有执行入口。V01 至 V04 仍需从原始资料独立验收。

## 3. 外部材料的采用边界

旧研究中的设计思路不等于可直接复制的代码或经验证的古建参数。

- 工具目录、参数校验、异常拒绝与运行记录已写入本地契约。当前维护以技术架构和源码为准，不重复维护一份外部项目字段对照。
- ACA-Builder 等参数化古建项目只作为构件表达与文献出处的研究线索。未固定仓库版本、取得许可并核对参数出处前，不引入代码或数值。
- 通用点云分割与机械 CAD 论文不能证明中国古建制作能力，旧文中的“学界最好水平”比较撤除。具体任务按 V06 另行验证。
- 旧 deepseek-harness 笔记未提供完整可定位的仓库地址与固定版本，本轮未将其重新确认为外部采用依据。

## 4. 后续引入条件

只有解决已确认制作缺口的候选技术才进入验证，未取得条件时状态为不采用。

**表 2：引入检查与失败处置**

| 检查 | 通过条件 | 缺少条件时 |
|---|---|---|
| 可复现来源 | 官方仓库、提交版本、许可证和相关文件均可定位 | 不复制代码或数据 |
| 任务匹配 | 输入与目标构件属于当前任务，输出能进入既有参数契约 | 不用结果截图代替接入证明 |
| 质量与人工投入 | 同资料、同质量门槛下通过并减少相应人工负担 | 不宣称提效，不进入默认流程 |
| 维护与恢复 | 依赖、成本、失败、数据迁移和回退明确 | 保留当前实现，补齐条件再评估 |

技术方案见[技术架构](../02_技术/01_技术架构.md)第 1.4 节，产品优先级以核心 PRD 为准。
