## 一、已裁决五条

### 1. 来源标记的另四类

**问题。** 视觉规范 v1.0 有五类来源标记（实测、AI 识别、自动核对、人工确认、示例资料），各一色一形。v3 只有实测一组（`--gb-color-source-measured` 三值），跑遍十九屏与 `V3/Tag` 组件集，另四类的色值与形状都没有。

**裁决。** 回 Figma 补齐四类。五类来源是本产品的核心表达，PRD 与界面文档都写了，不收敛。

**执行方式。** 建 v4 时按 v3 现有标签的形式补四组变量（`source-ai`、`source-autocheck`、`source-human`、`source-sample`，各含字、底、边三值），色相从 v1.0 迁移后按 v3 的中性灰调校一次。形状参数（点直径、描边宽、方点边长、斜线角度与线宽间距）v1.0 只给了形态名没给尺寸，一并在 v4 里定死。

### 2. 交互状态

**问题。** 悬停、按下、聚焦、禁用四态原型一处未画。十九屏画的都是默认态。v3 里唯一的 2px 边框用在框选边界示意上，不是聚焦环。

**裁决。** 按 v1.0 已有的规则推导，不回 Figma 补画。

**执行方式。** 沿用 v1.0 第 5.1 节规则：悬停在底色上加深 8%，按下加深 12%，聚焦为 2px 主操作色外框且不移除默认焦点，禁用用弱化文字色配次级底。规则作用到 v3 的新色上算出具体值。视觉规范 v2.0 里这几项必须标明是推导值而非原型值。

### 3. 行高不统一

**问题。** 13px 正文在原型里有 20、22、26 三个行高，12px 说明文字有 16、18、20 三个。原型没有给出哪个是基准档。

**裁决。** 不收敛。原型某处是多少就写多少。

**执行方式。** 视觉规范 v2.0 的字阶表按用途逐项列出，不合并成几个抽象档位。例如助手会话气泡记为 13/400/22，页面副标题记为 13/400/20，本次范围清单记为 13/400/26，各自标明用在哪里。这与 v1.0 的六档抽象法不同，是本次的有意改变：忠实照原型优先于规则简洁。

### 4. 主操作色

**问题。** 原型里主操作黑有三个值：主按钮 `#0a0a0a`，顶栏标识块与发送按钮 `#0d0d0d`，用户消息气泡 `#141414`。三者肉眼几乎无差，都不是变量。

**裁决。** 统一取 `#0a0a0a`，定义为 `--gb-color-action-primary`。

**执行方式。** 另两个值在规范里标明为原型未统一的历史值，不建令牌。v4 里三处统一改为 `#0a0a0a`。

### 5. 窄屏

**问题。** 十九屏全是 1440 × 900，没有第二档宽度，也没有断点标注。v1.0 那三条窄屏规则在原型里无从核对。

**裁决。** 窗口变窄时先收起右侧助手栏，再窄则左栏收为图标条，中间主区域不压缩。

**执行方式。** 落成具体断点：不小于 1280 时三栏全开（240 / 剩余 / 380）；1024 至 1279 收起助手栏，改为顶栏图标唤起；小于 1024 时左栏收为图标条；中栏最小宽 640。这些数值是按裁决推导的，规范里标明非原型值。

## 二、职责边界（2026-08-21 JIAJIA 定，最重要的一条）

**设计规范照原型完全还原；技术、内容、功能、流程由实现侧负责换成实际的。**

原文：设计规范细节这些内容按照原型图规定的来完全还原，但技术、内容、功能、流程这些东西自己负责换成现在实际的内容，不能因为原型图没有就把做了这么久的东西放弃展示。这是做 v4 的意义。

这条划清了两边：

| 归原型 | 归实现侧 |
|---|---|
| 字号、字重、行高、颜色、圆角、间距、按钮样式、标签样式、组件形态 | 有哪些页面、每页显示什么、阶段怎么分、页签怎么挂、数据从哪来、文案怎么写 |

因此下面七处疑点里，涉及信息结构与流程的由实现侧直接定，不再回问。

## 三、七处疑点的处置

### 1. 助手栏进度分母与阶段数不一致

原型写当前任务 · 3 / 7，左栏是八个阶段。

**处置：** 分母取真实阶段数 8，进度按当前所处阶段计算。原型的 7 是画图时的示意值。

### 2. 同一对象两种写法

顶栏面包屑写主殿正立面 1:50，左栏写主殿正立面建档。

**处置：** 顶栏面包屑显示项目名 / 建筑对象名 成果比例，左栏显示项目名与建筑对象名两行，均取自项目数据的真实字段，不再出现两种自由写法。

### 3. P01 两个新建入口

右上黑底按钮新建项目与右侧虚线卡建立新的单栋建筑任务。

**处置：** 同一动作，两个入口。按钮文案统一为新建项目，虚线卡保留为空态引导，卡内文案改为新建项目加一行说明。两者指向同一流程。

### 4. 用户消息气泡与主按钮同色

**处置（JIAJIA 定）：** 改成不同底色。气泡用浅灰底深色字，与黑底主按钮分开。这是对原型形式的一处有意修改，记入偏离清单。

### 5. P01 指标区的数字没有对应字段

原型显示待确认 3可导出成果 0，项目卡数据里没有这两个字段。

**处置：** 由前端从项目快照统计得出。待确认取问题队列里未解决项与候选待确认项之和，可导出成果取通过检查的成果数。统计口径写进实现说明。

### 6. 本次范围是整段文本

原型里是一个五行的文本节点，不是结构化字段。

**处置：** 拆成结构化字段渲染：建筑类型、对象、成果比例、负责人、复核人，各取自任务书的真实字段。排版沿用原型的逐行清单形式。

### 7. 阶段与页签多对多

原型里 02 与 03 共用一组页签，04 与 05 共用一组，06 与 07 重叠。

**处置：** 按第二节的职责边界，信息结构由实现侧定。改为每个阶段独占自己的视图，不共用：

| 02 整理资料 | 资料清单 | 项目资料 |

| 04 核对构件 | 构件清单、三维模型 | 对象与构件、三维模型 |
| 05 记录现状 | 现状记录、问题队列 | 现状记录、问题队列 |

| 07 检查签发 | 检查与资格 | 检查与资格 |

### 8. 操作人显示

## 七、2026-08-22 由 project-lead 决定的三条

这三条原本列为待 JIAJIA 定。JIAJIA 2026-08-22 指示把未解决的一并解决，故由 project-lead 按 CTO 职责判断并执行，理由与回退方式一并写在这里，随时可推翻。

### 1. v3 不分叉，共用一套组件

**背景。** v3 与 v4 共用 `V3/*` 组件，为 v4 改主组件时三处改动同时作用到 v3：顶栏导航项、用户消息气泡底色、标识块圆角与色值。v3 的内容一字未动。

**决定：不分叉。** 三处都是裁决要求改的项。复制出 `V4/*` 三份组件、把十九屏的实例逐个改指过去，代价是从此维护两套设计系统，而 v3 已经是 v4 的形式来源、不再是实现依据，为它保留一套会分叉的令牌不划算。

**已做。** 在 v3 页面左上放了一块状态说明，写明本页已被 v4 取代、继承了哪三处改动、以及要冻结的话怎么做。非破坏，任何时候可以按那段说明回退。

### 2. 两处一次性字号归到多数值

**背景。** W07 面板标题 17/Medium/26 与 B01 对话框标题 20/Medium/30，各只出现一次，同类用途的其余节点分别是 16/24（31 处）与 18/26（8 处）。

**决定：判为画图手误，归到多数值。** 理由是这两个值没有任何设计意图可循，留着会在样式表里各多出一个只用一次的字号。按裁决第 3 条不收敛的原则，是原型某处是多少就写多少；但那条针对的是有用途区分的多档行高，不是孤例。

**已做。** 两处已改，全页复查无残留。这是对原型形式的修改，记入偏离清单。

### 3. 来源标记不做形状，改口径为颜色加文字

**背景。** 视觉规范 v1.0 规定五类来源各有一种形状（实心圆点、空心圆点、方点、实心圆点加姓名、斜线底纹），但从未定义过尺寸参数，是长期悬空的缺口。

**决定：不补形状，改口径。** 来源标记用颜色加文字标签表达。`V3/Tag` 组件始终带文字，颜色只作辅助，v1.0 第 7 节要求的状态不能只用颜色表达（原文是必须同时有文字或形状）本来就已满足。补五种形状要为八个色调各做一套形状变体，收益只是冗余编码。

**已做。** 视觉规范第 2 节与第 7 节、README 的对应说法都已改写，缺口清单第 2 条标为收口。
