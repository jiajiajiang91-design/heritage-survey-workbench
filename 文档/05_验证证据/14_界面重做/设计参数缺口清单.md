# 产品原型 v3 设计参数缺口清单

日期：2026-08-21。依据：实施单元 05 第一组。

## 一、结论

53 处缺口。缺口的含义是：视觉规范 v1.0 规定了这一项，而 v3 原型里取不到对应值，或原型内部自相矛盾无法判定。

**这些项一律不填推测值。** 填一个看起来合理的值，后面没人能发现它不是原型定的，而当前 `styles.css` 里 585 处字面 px 正是这么积累出来的。

## 二、缺口逐条

### 字阶（9 条）

**字阶没有任何 Figma 变量定义，全部字号字重行高只能逐节点取属性**

取不到的原因：get_variable_defs 在页面节点 29:2 报错需要选中图层，在 39:2、39:53、45:1325 三个重点屏返回的变量集里只有 gb-color-*、gb-space-sm、gb-radius-full、gb-stroke-hairline 四类，没有任何 typography 变量。原型侧字阶是逐节点手工设置的，不是 token

建议：v2.0 把字阶定义在代码侧作为唯一权威 token，并记录一条待办：把 v2.0 的字阶回写成 Figma 文字样式或变量，避免下一轮再逐节点取值

**v1.0 的第六档「数值等宽 13/400/20」在 v3 没有对应物**

取不到的原因：所有数值文字都用 Noto Sans SC，不是等宽族。实测值 39:512（12.36 m）为 13/500/20，耗时 45:1293（2 分 18 秒）与费用 45:1294（¥ 4.80）为 13/400/20，时间戳 45:1356（今天 10:36）为 12/400/18。整个 v3 原型没有出现任何等宽字体族

建议：两选一并写清依据：一是 v2.0 取消该档，数值统一走 13/400/20 正文档；二是保留该档但明确标注这是代码侧新增、原型未验证，并在下一版原型补上

**备用字体族取不到，v1.0 的 Microsoft YaHei 回退在 v3 无对应属性**

取不到的原因：Figma 的文字节点只记录一个字体族，没有回退链的概念。get_design_context 返回的都是单一 font-['Noto_Sans_SC:Regular'] 或 Medium，无第二字体信息

建议：v2.0 里把回退链明确标注为代码侧决定（非原型取值），写成 Noto Sans SC 优先、系统中文字体兜底，并注明原型无此参数

**字重 600 在 v3 完全不存在**

取不到的原因：v1.0 六档里页面标题、区块标题、标签三档都写 600，但 v3 所有加重文字都是 Noto Sans SC Medium，映射到 font-weight 500。取遍五个屏与四个共享组件，没有任何节点使用 600 或 Bold

建议：v2.0 把这三档字重从 600 改为 500，与原型对齐；若前端确认 500 在实际渲染下压不住层级，要作为一次明确偏离记录下来，不要默认沿用 v1.0 的 600

**字间距（letter-spacing）无法确认是「设为 0」还是「未设置」**

取不到的原因：get_design_context 返回的类名里没有出现任何 tracking-* 类，说明渲染值等于默认，但工具输出不区分显式 0 与未设置，从返回结果无法判定原型是否做过这项决策

建议：v2.0 直接定为 0（normal），并在参数表里标注来源为「原型未设置，按默认取 0」，不要写成从原型取到的值

**13px 正文与 12px 说明文字各有三个不同行高，原型没有给出哪一个是基准档**

取不到的原因：13px 正文出现 20px（39:19、39:44、45:1292）、22px（36:30、39:217）、26px（39:216）三种行高；12px 说明文字出现 16px（36:23）、18px（39:24、45:1356）、20px（36:20、37:18）三种。这是原型内部的不一致，不是取值失败，从原型无法判定设计意图

建议：提请设计侧确认后再落入 v2.0。可行的收敛方向是：单行场景取 13/20 与 12/18，多行段落场景取 13/22 与 12/20，26px 只保留给 W01 本次范围那类逐行清单；但这个收敛必须由设计确认，不要由规范文档自行选定

**v1.0 的「页面标题 18/600/26」一档与 v3 无法一一对应**

取不到的原因：v3 把页面标题拆成了两个层级：全局页（P01/P02/P03）用 28/500/38，工作区页（W01 等中栏）用 22/500/30；而 18px 在 v3 是卡片标题（39:40 项目名）的字号。v1.0 的档位划分与 v3 的结构不同构

建议：v2.0 按 v3 结构重新分档：全局页标题 28、工作区页标题 22、卡片标题 18、区块标题 16 四档并列，不要把 v3 的值硬塞进 v1.0 的六档骨架

**部分文字节点自身没有行高属性，行高由父容器继承**

取不到的原因：左栏导航项 34:15 / 34:16 / 34:17 与 P02 表头 45:1285-45:1289 的行高分别写在父容器 37:20（leading-20px）和 45:1284（leading-18px）上，节点级取不到。这类值取自父级，与其他档的取值口径不同

建议：v2.0 在这两条上注明行高来源是父容器，实现时按父容器统一设定；同时提醒前端不要在子节点上再覆写行高

**18 个屏中只逐屏核对了 5 个，其余 13 个屏未取值**

取不到的原因：本次按任务范围只取了重点屏 P01 39:2、W01 39:53、P03 45:1325，另抽样了 P02 45:1250 与 W03 39:386，加上四个共享组件（Topbar 35:14、Left Rail 38:444、Assistant Panel 36:14、Tag 31:9）。W02、W04 至 W10、W04A、W09A 及 B01 至 B04 未逐一核对，可能存在未列出的字阶组合

建议：v2.0 定稿前对剩余 13 屏做一次字阶差异扫描，重点看 W08 图纸样式与 W09 图纸与检查这类可能带专业标注文字的屏；若时间不允许，在规范里注明字阶清单的核对范围仅覆盖上述 5 屏与 4 个共享组件

### 基础色（4 条）

**强调边框（比常规边框更重的一档）**

取不到的原因：v3 只有两级边框变量：--gb-color-border-default #d4d4d4 和 --gb-color-border-subtle #e5e5e5，后者比前者更浅。没有任何比 #d4d4d4 更深的边框变量或节点属性。v1.0 的八项基础色里「常规边框／强调边框」在 v3 对应的是「常规边框／弱化边框」，是一次方向相反的改动

建议：在 v2.0 里按 v3 现状记为 border-default 与 border-subtle 两级，并单独记一条「v1.0 的强调边框在 v3 已取消」；若前端确有需要强调的边框场景（例如选中卡片外框），需要先在原型里指定该场景再定值

**共享组件的颜色未接入变量体系，另用一套灰阶**

取不到的原因：V3/Topbar 35:14、V3/Left Rail 38:124、V3/Assistant Panel 36:14、V3/Info Row 33:39 四个组件对 get_variable_defs 返回空（如 39:219 返回 {}），内部全部是裸色值：边框 #e6e6e6 / #e0e0e0 / #d6d6d6，文字 #1a1a1a / #1f1f1f / #262626 / #333333 / #404040 / #616161 / #666666，选中底 #ebf5ff。这些值和变量体系里的 #d4d4d4 / #e5e5e5 / #171717 / #525252 / #737373 / #eff6ff 一一相近但都不相等

建议：v2.0 收口时必须做一次映射表，把这十几个裸色值归并到变量体系里（例如 #e6e6e6 与 #e5e5e5 合并、#333333 归入 #525252、#ebf5ff 归入 #eff6ff），并在规范里写明前端以变量值为准、原型的裸色值不再复现

**页面底 #fafafa 的实际可见位置**

取不到的原因：用 get_variable_defs 逐层收敛确认：--gb-color-bg-canvas 只出现在画板节点（39:218 有，Workspace 39:231 没有，Topbar 实例 39:219 返回空），说明它绑定在画板填充上；而画板被顶栏（白）与 Workspace（左栏 #f5f5f5、中栏 #ffffff、助手栏白）完全覆盖。也就是说这个值在 v3 的任何一屏里都看不见

建议：v2.0 里要么明确 #fafafa 作为浏览器 body 底色（超出 1440 宽或内容不满高时可见），要么删掉这个令牌。不要写成「中栏底色」，中栏在原型里是纯白 #ffffff（39:299）

**暗色模式色板**

取不到的原因：文件里所有变量只有一套值，get_variable_defs 未返回任何模式维度，19 屏也没有暗色版本

建议：v2.0 明确写「只支持浅色，暗色不在本版范围」，避免前端自行推导一套暗色

### 语义色（5 条）

**主操作色没有变量，且原型里存在三个不同深色**

取不到的原因：跑遍 19 屏的 get_variable_defs，没有任何 primary/action 类变量。主按钮底是裸色值 #0a0a0a（39:20、39:538、43:924、44:1119、45:1665），顶栏标识块和助手发送按钮是 #0d0d0d（I41:342;35:16、36:39），助手用户消息气泡是 #141414（36:33）。三者肉眼几乎无差，属于原型未统一

建议：v2.0 定一个 --gb-color-action-primary，取用得最多的 #0a0a0a 作为唯一主操作色，并在规范里明示 #0d0d0d 与 #141414 是需要合并的历史值，不作为新令牌

**主操作的悬停态与按下态**

取不到的原因：原型里没画。全文件节点名检索 Hover／Pressed／Active／Focus／Disabled／悬停／按下／禁用 全部零命中，Button 类节点只有默认态一份

建议：这是前端必须有、原型没给的值，属于新定而非取值。建议在 v2.0 里以 #0a0a0a 为基准明确写出推导规则（例如悬停提亮一档、按下压暗一档）并标注为规范新增、原型未验证，等原型补画后再对齐

**主操作的浅底（v1.0 四组语义色各含主色与浅底，主操作组的浅底在 v3 无对应）**

取不到的原因：v3 没有 primary 系列变量，自然也没有 primary 浅底。最接近的 --gb-color-bg-selected #eff6ff 实际用途是选中态底色（标签页 41:454、对比卡 45:1639、选项行 45:1657），不是主操作的浅底

建议：不要把 #eff6ff 直接当主操作浅底写进规范。先确认 v2.0 是否还需要「主操作浅底」这一档；需要则在原型里指定用途再取值

**单选圆点的选中色与未选中色**

取不到的原因：B02 的三个选项圆点（45:1648、45:1653、45:1658）是矢量，get_design_context 只返回导出后的 SVG 资源链接，不返回填充色；节点上也没有绑定变量。要拿到必须下载 SVG 或截图量取，本次未做下载

建议：若 v2.0 需要单选控件规格，单独跑一次：对 45:1658 取 get_screenshot 后量取，或让设计把圆点改成绑定变量的矢量再取。在拿到之前不要填值

**危险色的按钮态与横幅态**

取不到的原因：危险色在 v3 只以标签形式出现（30:17 Tag Tone=Danger）。W09 的「局部退回」44:1117 和 W09A、B04 的同名按钮都是常规次要按钮（白底 #ffffff、常规边框 #d4d4d4、主文字色），没有任何危险色按钮或整块危险底的提示条

建议：v2.0 只按原型记「危险色仅用于标签」；若前端需要危险按钮（例如删除、退回确认），属于新增设计，需先在原型里补画

### 来源标记（3 条）

**AI 识别、自动核对、人工确认、示例资料四类来源标记，色值与形状全部缺失**

取不到的原因：全 19 屏跑了 get_variable_defs，来源类变量只有 --gb-color-source-measured 一组（fg/bg/border）。V3/Tag 组件集 31:9 只有 Neutral/Info/Success/Warning/Danger 五个语义调，没有任何按来源分类的变体。逐屏查了 W02 39:218、W03 39:386、W04 41:341、W05「Evidence source」42:704、W06「Model legend」42:830，出现的标签文字只有 实测／仅参考／抽样／照片估算／可用／待核对／待确认／已确认／待执行／进行中／需专业判断／通过／待签，没有一处写 AI 识别、自动核对、人工确认或示例资料。W05 42:709 的「人工记录，等待专业判断」是正文句子，不是标记

建议：不要用 v1.0 的旧值补。先做产品判断：五类来源是否仍是 v2.0 的表达骨架。若是，需要在 Figma 里补齐 source-ai / source-autocheck / source-human / source-sample 三值一组的变量并落到 V3/Tag 变体，再重新取值；若已决定收敛成一类来源加语义状态，则在视觉规范 v2.0 里明确写「来源只保留实测一色」，并同步改 PRD 与界面设计规范里关于五类来源的描述

**点直径、描边宽、方点边长、斜线角度与线宽间距等形状尺寸**

取不到的原因：v3 原型里来源标记没有形状层。31:9 组件集五个变体每个只含一个文字节点，没有 ellipse、rect 或 line 子节点，也没有任何图案填充。取不到不是因为工具限制，是因为原型里不存在

建议：若 v2.0 要恢复形状编码（色觉障碍与黑白打印场景需要），这是新设计而非取值，应在原型里先画出来再取；在此之前视觉规范 v2.0 只能写「v3 用文字区分来源，形状编码待补」

**来源色的唯一语义**

取不到的原因：--gb-color-source-measured 这组蓝色被当成通用 Info 调复用：W02 39:357 的「仅参考」、B04 46:1710 的「可查看」、W08 43:1079 都用同一组值。同一颜色同时表示「实测来源」和「仅供参考」，与 V3/Tag 组件说明「来源与状态必须使用不同实例，同一标签只表达一种含义」自相矛盾

建议：v2.0 定令牌时把来源色和信息色拆成两个名字（例如 source-measured 与 status-info），即使初期同值；并在规范里逐条列出哪些标签文字属于来源、哪些属于状态

### 间距与形态（8 条）

**间距档位的变量名。v3 只有 --gb-space-sm = 8 一个间距变量，实际用到的 4、6、10、12、16、20、24 都以裸数值写在节点上，没有名字。**

取不到的原因：get_variable_defs 在 19 个顶层屏上逐个查询，返回的数值型变量只有 --gb-space-sm、--gb-radius-full、--gb-stroke-hairline 三个，其余全是颜色。原型作者只给 8 这一档建了变量。

建议：v2.0 自己定名并回填，不要等原型。建议档位按 v3 实际用量定为 4 / 8 / 12 / 16 / 24 五档主档，把 6、10、20 三个例外单独处理：6 只出现在标签页竖内边距和 W09 紧凑面板，10 只出现在紧凑卡内边距，20 只出现在顶栏，可以各自并入 8 / 12 / 24，也可以保留为组件专用值但必须在规范里点名，不能混进通用档。

**聚焦态边框宽（v1.0 规定的 2px）。**

取不到的原因：v3 原型里根本没有交互态。对 29:2 全页 metadata 做过关键字遍历，Focus、Hover、Active、Disabled、Error 命中数全为 0，19 屏没有任何一个控件画了焦点态、悬停态或禁用态。全页唯一的 2px 边框是 41:679 的框选边界示意（蓝色虚线），性质不同，不能当聚焦环用。

建议：聚焦态在 v2.0 里定为无原型依据的新增项，明确标注。建议沿用 v1.0 的 2px，但因为 v3 常规边框已经统一到 --gb-stroke-hairline = 1，聚焦环用 2px 实线加 v3 已有的 --gb-color-source-measured-fg #1d4ed8，与选中底色 --gb-color-bg-selected #eff6ff 成一套。这个决定要在规范里写明是补的，不是原型定的。

**面板圆角与控件圆角的变量名。8 这一档没有变量。**

取不到的原因：get_variable_defs 只返回 --gb-radius-full = 999。面板、卡片、按钮、输入框、标签页、导航项的 rounded-[8px] 全是硬编码。

建议：v2.0 建两个名字，值都取 8：面板圆角和控件圆角合并为一档。v1.0 的 10 和 7 两档在 v3 已经全部收敛到 8，唯一残留是顶栏品牌标记 I39:54;35:16 的 7px，建议一并改成 8 并在改动记录里写清；复选框的 4px 是刻意的小控件值，单独保留。

**悬浮层阴影参数。v1.0 写了不用阴影表达层级、只有悬浮层例外，但 v3 的例外没兑现。**

取不到的原因：这不是取不到值，是设计里就没有。W04A 41:673、W09A 44:1275、B01 45:1451 三个弹层的节点属性只有背景色、1px 边框、8px 圆角、24px 内边距，没有任何 effect。v3 改用遮罩 rgba(13,13,13,0.38) 表达层级。

建议：v2.0 有两条路，需要 JIAJIA 拍板：一是删掉悬浮层阴影例外条款，全站按 v3 的做法用遮罩加 1px 边框，规范因此更简单；二是保留例外条款，但阴影参数没有原型依据，需要新定并标注为新增。倾向第一条，理由是 v3 三个弹层都已经验证过遮罩方案可读。

**卡片内边距的选用规则。v3 实际有 16、12、10 三档，但没有任何依据说明什么时候用哪档。**

取不到的原因：三档都能从节点属性取到确切值，取不到的是规则本身，Figma 里没有对应的组件描述或注释。观察到的相关性是卡片宽度：552 用 16，254 到 356 用 12，232 到 314 用 10，但 12 和 10 的宽度区间有重叠，不能反推出确定规则。

建议：v2.0 按用途定规则而不是按宽度：主内容卡用 12，只承载一行事实加一个状态标签的信息行卡用 10。或者更省事的做法是把 10 并入 12，只留 16 和 12 两档，代价是 W03 实测基准、W09 检查项面板的卡片会变高，需要确认这两屏的纵向空间是否还够。

**区块间距的统一口径。v3 工作台屏用 12，列表页用 24，两者相差一倍，没有变量也没有说明。**

取不到的原因：两个值都从节点属性确凿取到（39:134 与 39:15），取不到的是为什么不一致。Figma 里没有说明这是刻意区分还是不同时间画的结果。

建议：按信息密度分别定，写进规范：工作台屏三栏布局、中栏可用宽度只有 788，区块间距 12；列表页单栏、左右留白 160，区块间距 24。两个值都保留，但必须各自绑一个变量名并写明适用场景，否则前端会随手挑一个。

**v1.0 的 32 档去留结论。**

取不到的原因：32 在 v3 全页完全没出现。对 29:2 做了全量几何遍历，并对 8 个屏逐项核对 get_design_context 返回的内边距与间距，都没有 32。取不到的是这属于原型作者主动删档还是遗漏。

### 组件尺寸（13 条）

**按钮的横向内边距规则**

取不到的原因：原型里所有按钮都是固定宽度加内容居中，没有用自动布局的内边距。实测留白随宽度浮动：104px 按钮留 26px，96px 按钮留 22px，116px 按钮留 25.5px，不存在一个统一值可以取

**图标按钮的方形尺寸**

建议：定为 32x32，圆角 8px，与页签同高，图标区 16x16。工具栏密集处可另出 28x28 一档。这一项必须在前端开工前补进原型，否则框选修正、三维视图这类需要工具条的屏幕没有依据

**危险按钮样式**

取不到的原因：原型里语义上属于危险操作的按钮全部沿用黑色主按钮。44:1304 确认退回、44:1119 通过检查、43:924 确认判断的填充都是 #0a0a0a，与 39:212 进入资料清单完全相同，没有任何红色变体

**文字按钮样式**

取不到的原因：全页 34 个 Button 实例只有两种样式：黑底白字主按钮、白底 1px #d4d4d4 描边次按钮。没有第三种无底无框的文字按钮。顶栏的项目列表、运行与费用、修改历史（I39:54;35:23 至 35:25）是纯文本 13px Regular #666，属于导航链接而不是按钮组件

建议：定为高 32px、横向内边距 8px、无底无框、文字 13px Medium #525252，悬停时底色 #f5f5f5。仅用于卡片内的次要操作，正式动作区仍只用主按钮和次按钮两种

**按钮的悬停态、按下态、禁用态**

取不到的原因：Figma 组件里按钮没有做成带变体的组件，全部是散装 frame，因此不存在交互状态的定义

建议：主按钮悬停 #262626、按下 #000000；次按钮悬停底色 #f5f5f5、边框不变；禁用统一为文字 #a3a3a3、底色 #f5f5f5、边框 #e5e5e5、不可点击

**表格数据行的选中态**

取不到的原因：P02 是全页唯一的真表格，五行 Run row（45:1290 起）样式完全一致，没有任何一行被标为选中。卡片式列表有选中态（W07 43:877 换底 #eff6ff），但表格行没有对应示例

建议：沿用列表卡片的做法，选中行底色换 var(--gb-color-bg-selected) = #eff6ff，下边框保持 #e5e5e5 不变。同时补悬停底色 #fafafa，与选中态区分开

**输入框的聚焦态与错误态**

取不到的原因：B01 新建任务的六个输入框（45:1463 起）都是同一种静态样式，没有做变体，Figma 里也没有聚焦或校验失败的示例

建议：聚焦时边框换 #1d4ed8（复用来源标记的 fg 色）并加 2px 同色低透明外发光；错误态边框 #b91c1c，下方加 12px / 行高 18px 的错误文字。这两项由前端定，定完回填原型

**输入框只有一套统一规格**

取不到的原因：取到两套互不兼容的输入框：表单输入框高 36px、左右内边距 12px、边框变量 #d4d4d4；助手面板输入框高 46px、四周内边距 12px、边框硬编码 #d6d6d6。两者都是原型现状，无法判断哪个是基准

建议：以表单输入框（36px、边框变量 #d4d4d4）为单行输入的基准，助手面板改为多行输入的独立规格并把边框改绑同一变量。#d6d6d6 这个硬编码值直接废掉

**选中态蓝色只有一个值**

取不到的原因：取到两个不同的选中蓝：页签和列表卡片用变量 var(--gb-color-bg-selected) = #eff6ff，左栏当前任务项（V3/Task Nav Item 34:18）用硬编码 #ebf5ff。两值相差极小但确实不同，属于原型内部冲突

建议：统一为变量值 #eff6ff，左栏那处硬编码作废。这一条建议同步给负责语义色的人，避免两边各定一套

**主按钮黑色只有一个值**

取不到的原因：按钮填充是 #0a0a0a，但顶栏品牌方块（I39:54;35:16）和助手面板发送按钮（I39:135;36:39）是 #0d0d0d。三处都没有绑变量

建议：统一为 #0a0a0a 并建变量 --gb-color-action-primary-bg。发送按钮属于按钮，必须跟主按钮同值；品牌方块如果要保持独立，单独出一个品牌色变量而不是留一个孤立硬编码值

**组件尺寸类的变量支撑**

取不到的原因：变量表里只有颜色，加上 --gb-space-sm=8、--gb-radius-full=999、--gb-stroke-hairline=1 三个非颜色变量。按钮高 36、页签高 32、标签高 22、圆角 8、表头圆角 6、内边距 12 与 16、表格行高 56 全部是节点上的硬值，没有任何变量承载

建议：补一组尺寸变量：--gb-size-control=36（按钮与输入框）、--gb-size-tab=32、--gb-size-tag=22、--gb-radius-md=8、--gb-radius-sm=6、--gb-space-md=12、--gb-space-lg=16。表头圆角 6px 是全页孤例，建议直接并入 8px，少一档规格

**页签的悬停态与禁用态**

取不到的原因：页签在 Figma 里是散装 frame 不是组件变体，只做了选中与未选中两态

建议：悬停时未选中页签加底色 #f5f5f5，文字色不变；禁用文字 #a3a3a3 且不响应悬停

**卡片的层级区分手段（阴影或替代方案）**

取不到的原因：全页零阴影，容器卡、嵌套小卡、指标卡和四个弹窗用的是同一套 1px #d4d4d4 边框加 8px 圆角，弹窗与页面内容的层级只靠遮罩层拉开

建议：保持零阴影这一决定，它和这套界面的克制风格一致。层级改用内边距区分：容器卡 16px、嵌套小卡 12px、弹窗 24px，已经形成三档，写进规范即可。弹窗遮罩的具体色值和透明度需要另行确认，本次未取

### 布局尺寸（11 条）

**窄屏形态完全没有画**

取不到的原因：29:2 页下 19 个画板全部是 1440 × 900，没有任何第二档宽度的画板，也没有断点标注。v1.0 规定的三条窄屏规则（优先收起右栏、其次左栏收为图标条、中栏不压到 640 以下）在 v3 找不到任何对应画面，无法核对具体像素值和收起后的形态。

建议：两条路选一条。一是规范里直接把 v1.0 三条规则落成数值：≥1280 三栏全开（240 / 剩余 / 380）；1024 至 1279 收起助手栏，改为顶栏图标唤起的浮层；<1024 左栏收为 56 宽图标条；中栏 min-width 640。二是回 Figma 补画 1280 和 1024 两档画板再取值。在补画之前，规范里这部分必须标为待定，不要写成已定尺寸。

**中栏是固定 820 还是取剩余宽度，取不到**

取不到的原因：只有一档画布宽度，820 恰好等于 1440 − 240 − 380，从单一画板无法区分“中栏固定 820”和“中栏 = 剩余宽度”。这两种实现在窗口缩放时表现完全不同。

建议：定为：左栏 240 固定、助手栏 380 固定、中栏 flex:1 取剩余宽度，最小 640。同时把 820 记为 1440 视口下的实测值而非固定值。

**全宽页面两侧 160 的性质取不到**

取不到的原因：同上，160 + 1120 + 160 = 1440 恰好铺满，无法区分“左右各 160 固定内边距”和“内容 1120 定宽居中”。

建议：定为内容最大宽度 1120、水平居中，两侧最小内边距 24。这样在窄屏下内容会自动收窄而不是被裁掉。

**全宽页面顶部留白有两个值，规范无法二选一**

取不到的原因：P02（45:1264）和 P03（45:1339）是 36，P01（39:16）和 B01（45:1402）是 40。原型里两套值并存，没有标注说明哪个是对的，也看不出差异是有意还是画偏。

建议：统一取一个值写进规范，建议 40（与左栏、助手栏的 16 上下内边距和中栏 16 内边距形成 40 / 16 两级层次更清楚）。定完后回 Figma 把另外两页改齐，避免规范和原型对不上。

**中栏底部留白的规则取不到**

取不到的原因：中栏是 padding 16 的纵向自动布局，但主内容块写死高度 650，导致内容底部到画板底部余 64（16 内边距 + 48 未填满）；W01 因为多一个指标区，只余 34。这个 64 和 34 都是高度写死后的剩余，不是设计定的底部留白，规范里照抄会把偶然值变成规则。

建议：规范里不要写“底部留白 64”。改成：中栏主内容区高度 = 剩余可用高度（flex:1），底部内边距固定 16，内容超出时主内容区内部滚动。650 只作为 1440 × 900 下的参考值记录。

**助手栏“五段”与 v3 的实际结构对不上**

取不到的原因：v3 的 V3/Assistant Panel（36:14）是三段容器：头部 56 / 会话区 670 / 输入区 118。组件说明也只写了三部分。要凑成五段，只能把会话区拆成任务状态 98 和消息区 300，把输入区拆成输入框 46 和操作行 36，但这样是四加二共六块，且拆法不唯一。

建议：规范改写为“三段容器 + 五个内容块”：容器为头部 56（固定）、会话区 flex:1、输入区 118（固定）；内容块为任务状态卡 98、消息区 flex:1、输入框 46、操作行 36。不要保留“五段”这个说法，它在 v3 里没有对应物。

**助手栏消息区的伸缩规则取不到**

取不到的原因：会话区 670 高，内部只用了 446（16 + 98 + 16 + 300 + 16），底部空 224。消息区写死 300 高。无法判断这 224 是留给消息增长的预期空间，还是画稿没填满。

建议：定为：消息区 flex:1 填满会话区剩余高度，内部纵向滚动，新消息置底。300 只作为参考值记录。

**弹层遮罩作用域为什么分两套，没有说明**

取不到的原因：工作台弹层（W04A 41:672、W09A 44:1274、B02 45:1634、B03 46:1692）遮罩只有 820 × 844，盖住中栏；项目级弹层（B01 45:1450）遮罩 1440 × 900 盖整屏。原型里没有任何标注说明弹层打开时左栏和助手栏是否还能点。

建议：明确写成规则：工作台内的修正类弹层为中栏内联弹层，遮罩只盖中栏，左栏与助手栏保持可交互（便于边看助手建议边改）；项目级弹层（新建任务等）为整屏弹层，遮罩盖全部。这条要请产品确认后再定稿。

**弹层的最大高度与内容溢出规则缺失**

取不到的原因：三个弹层高度都写死（700 × 560、680 × 540、720 × 700），原型只画了内容刚好放下的一种情况，没有画内容变长时的形态，也没有滚动条。

建议：定：弹层 max-height = 遮罩高度 − 96，标题区与操作行固定，中间内容区超出时纵向滚动。三个已知宽度 700 / 680 / 720 建议归并成两档（中 680、大 720），减少无意义的差异。

**没有任何布局尺寸类的变量**

取不到的原因：get_variable_defs 返回的全是颜色变量，与尺寸相关的只有 --gb-space-sm=8、--gb-radius-full=999、--gb-stroke-hairline=1 三项。栏宽、内边距、间距、条目高度全部是节点上的直接数值，没有绑定变量，改一处不会同步。

建议：在视觉规范 v2.0 里补一组布局变量：--gb-layout-topbar-h=56、--gb-layout-rail-w=240、--gb-layout-assistant-w=380、--gb-layout-center-min-w=640、--gb-layout-page-max-w=1120，以及间距梯度 4 / 8 / 12 / 16 / 24 / 40。前端按变量实现，后续回 Figma 补建同名变量。

**断点的具体像素值没有依据**

取不到的原因：v1.0 只有“窄屏”这个定性说法，v3 没有画板，整个文件里找不到任何断点数值。

建议：按内容反推定两档：1280（三栏全开的下限，240 + 640 + 380 + 边距 ≈ 1280）和 1024（助手栏收起后的下限）。这两个值是按 v1.0 的 640 中栏下限算出来的，规范里要标明是推算依据而不是原型取值。
