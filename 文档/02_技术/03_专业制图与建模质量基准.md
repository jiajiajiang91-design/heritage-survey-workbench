# 03 · 专业制图与建模质量基准 v1.1

## 1. 结论

当前制作案例必须在约定范围内保证尺寸、构件表达、同源视图和可编辑文件质量，资料不足时明确缺项。

完整古建单体的专业质量要求保留，但不把所有图种、隐蔽构造和修缮说明强加给受限资料任务。当前任务范围以演示项目定义第 3 节为准；超出范围的对象不计为已完成。

旧 T0 与里程碑验收保留在验证证据和历史任务中。它们不自动通过 PRD v4.0 的制作验收，也不因本轮调整而改写历史结果。
## 2. 依据与边界

### 2.1 依据

内部制作验收采用本文件的明确条件，真实项目另核对地区、对象与委托要求。

- CH/T 6005-2018《古建筑测绘规范》在[全国标准信息公共服务平台](https://std.samr.gov.cn/hb/search/stdHBDetailed?id=8B1827F2417CBB19E05397BE0A0AB44A)标为现行，查询日期为 2026-09-05。
- 北京 DB11/T 2546-2026《历史建筑信息采集与数字化技术标准》已于 2026-06-01 发布，将于 2026-12-01 实施。截至 2026-09-05 尚未实施，不能称为当前生效依据。来源为[正式文本封面与实施通知](https://ghzrzyw.beijing.gov.cn/biaozhunguanli/bz/ch/202607/P020260730536325575399.pdf)。
- HABS 图纸只支持指定历史建筑的资料转写和内部质量核对，不能证明符合中国古建项目的全部规范。
- JIAJIA 提供的参考图与外部 DWG 仅用于表达深度对照。具体建筑、尺寸和图元不能进入生成输入。检查记录见[外部参照检查](../05_验证证据/04_T0_CAD可行性与资产保全/外部DWG参照检查_寺庙古建筑设计方案图.md)。

本文件的数值门槛为项目验收约定，除明确引用外不声称来自某条国家或地方标准。正式项目的标准版本、适用条款与责任人必须在任务要求中登记，尚未完成这一工作时不得宣称规范符合性。
### 2.2 成果等级

L0 至 L3 是本项目内部验收分类，不是法定质量或资质等级。

| 等级 | 用途 | 可以包含的内容 | 不得宣称 |
|------|------|----------------|----------|
| L0 技术链路样例 | 验证 IFC、GLB、DXF、SVG、PDF 和外部软件 | 简单几何、少量标注、技术日志 | 专业模型、专业图纸、交付成果 |
| L0+ 古建语义技术样例 | 验证古建对象分类、曲线或阵列、图层和多格式生成 | 简化构件、示意视图、兼容性记录 | L1 局部专业样板、同源剖切、专业图面 |
| L1 局部专业样板 | 验证一组古建构件、屋面和详图能力 | 完整局部构造、来源和未知项 | 完整单体成果 |
| L2 单体专业成果 | 完成一座资料充分建筑的全套单体成果 | 三维、总平或定位、平立剖、详图、表格和报告 | 正式签发，除非责任条件满足 |
| L3 正式成果 | 责任人员审核、签名、验签并发布 | L2 全部内容和正式责任记录 | 超出资料、规范和签发范围的结论 |

当前制作案例按第 7.1 节验收；L1 至 L3 仅在相应专业样本和责任条件满足后评定。

### 2.3 展示与制作验收

成果展示、原始资料制作和专业适用性使用不同证据，分别判定。

两个公开项目保留已生成成果，检查查看、修改与导出。不同资料允许不同构件深度，但必须明示范围与简化说明，不能为追求一致外观补造构件。

T-DL-01 从原始资料开始验证 V01 至 V04。目标视图必须同源生成；资料不足、文件缺失或尺寸错误不能用演示包替代。

V06 使用合格中国古建资料与目标专业人员核对。演示数据保持其模拟来源；只读流程签发记录不构成真实工程效力。
### 2.4 待核对预览

待核对预览用于发现和修正问题，核对后成果继续按本次质量要求验收。

候选可以在原图标记、对象列表或具备参数的几何中呈现，来源冲突和未知项在相关对象显示。没有几何依据时保留原图，不画确定构造。预览不要求先通过全部成果检查，但必须准确表达所处状态。

采用候选后形成用于生成的记录，模型与图纸仍使用同一几何版本。V03 判断核对后成果，预览可见不作为质量通过。T-DL-03 的尺寸核对清单仅属于局部验证，不能当作 T-DL-01 的模型与图纸。

## 3. 三维模型最低要求

### 3.1 形制与构件

模型必须按资料支持的实际形制表达。矩形或平面只有在表达对象确为该形状时使用，不能替代资料已明确的曲线与节点。

资料中存在的下列对象应建立独立、可选择、可追踪的构件：

- 台基、阶梯、地面、散水、栏杆和附属墙体。
- 柱、梁、枋、檩、椽、望板及其上下、内外关系。
- 斗栱、撑拱、雀替或其他承托构件；建筑本身没有时标记为不适用。
- 屋面曲线、举折或举架控制、檐口、戗脊、正脊、垂脊、瓦面和饰件。
- 墙体、门、窗、槛墙、隔扇、格心或花格。
- 楼层、回廊、附属屋面和相接建筑。

每个构件保存稳定 `entityId`、类型、位置、几何、材料、来源和状态。重复构件使用可复用族或实例，不复制成失去语义的散乱网格。

### 3.2 几何与来源

模型与图纸采用同一几何版本，来源和未知项随对象保留。

- 屋面曲线使用可追溯的控制点、曲线或曲面，不用视觉近似替代可用测量。
- 三维模型与二维视图使用同一 `GeometryRevision`。
- 剖面必须由三维构件真实剖切，不能另画一套不相干的二维图。
- 二维生成器不得根据跨度、屋面公式或尺寸参数重新画建筑几何。平面、立面、剖面和详图中的结构性图元必须来自同一几何版本的投影、剖切或受控展开。
- `measured`、`model`、`rule`、`human` 和 `demo` 内容在数据中可区分。
- 资料不支持的暗构造保持未知、局部缺口或推断状态，不补默认斗栱、椽数、瓦数或基础做法。
- 模型节点可从三维视图追溯到事实、证据和人工决定。

### 3.3 三维验收

按任务范围检查所需交换格式与构件，不能用数量或名称代替形状和关系核对。

- IFC 保留对象分类、稳定 ID、属性和来源引用。
- GLB 保留与 IFC 对应的稳定节点 ID，可在网页中选择构件。
- 模型在独立查看器中无破面、反面、无限值、严重穿插和非预期悬空。
- 构件数量、总体尺寸、关键标高和轴网与项目事实一致。
- 预览至少提供轴测图、正交视图、剖切和按来源状态着色。
- 每个构件记录 `geometryStatus`：`resolved`、`simplified`、`placeholder` 或 `unknown`。L1 必需构件必须为 `resolved`；简化体块和占位构件不能计入 L1。
- 屋面、柱梁枋、檩椽、承托、柱础、台基和基础形成可查询的连接关系。非预期悬空和穿插必须为零。
- `representation` 名称不能代替几何检查。瓦件、屋脊、斗栱、门窗和屋面曲线必须通过截面、曲率、分格、拓扑和连接特征验证。
- L1 必需构件实例必须可追溯、无合并网格替代，并在声明容差内满足封闭性、包围盒、体积和关键点金标准。

## 4. 图纸最低要求

### 4.1 图种

完整单体专业任务在资料充分且委托要求覆盖时检查以下图种。当前受限制作任务仅检查已经冻结的目标视图。

- 总平面或可追溯的建筑定位图。
- 各层平面、屋顶平面和必要的仰视平面。
- 任务要求的各向立面。
- 穿过主要结构、屋面和高差关系的横剖面与纵剖面。
- 屋脊、檐口、斗栱、柱础、门窗、栏杆或其他关键构件详图。
- 门窗表、材料表、病害表和图纸目录。
- 现场照片或证据索引与图纸对象的对应关系。

某一图种不适用时记录 `notRequired`。资料不足时记录明确阻断码，不得输出空图或用通用构造补齐。

### 4.2 图面内容

每张图按用途至少检查：

- 图名、图号、比例、图幅、图签、修订和打印设置。
- 定位轴线、轴号、剖切符号、索引符号、详图符号和北向。
- 总尺寸、轴线尺寸、开间或进深尺寸、构件定位尺寸和必要净尺寸。
- 室内外标高、檐口、屋脊、楼层、台基和基础标高。
- 粗细线层级、可见线、剖切线、投影线、隐藏线、中心线和辅助线。
- 每条结构线归入剖切、轮廓、特征、构件边界、可见或隐藏类别，并关联源构件；三角网内部边不得进入图纸。
- 材料边界、剖面填充、地面线、墙体、木构、瓦面和基础做法。
- 构件名称、规格、做法、病害、修缮或保护说明。
- 现场事实、推断、拟修内容和新作内容的图层或符号区分。
- 尺寸和说明不得遮挡主体，密集区域使用索引详图或分图表达。

### 4.3 图面细节层级

图面细节按出图比例确定，不把模型的全部几何无差别投影到图纸上；三维模型保持精细，图纸按比例取舍，两者相互独立。

项目约定的判定基线是打印后的可辨间距：同类重复图元在成图上的间距小于 0.5 mm 时必须合并为简化表示或改用图例，否则打印后糊成实块。1:50 对应实际 25 mm，1:100 对应 50 mm。

| 比例 | 瓦面 | 斗栱 | 椽 | 构件分缝 |
|------|------|------|------|----------|
| 1:200、1:150 | 材质图例，不画垄 | 位置示意块 | 不画单根 | 不画 |
| 1:100 | 简化垄线，间距不小于 0.5 mm | 外轮廓 | 按檐口示意 | 主要分缝 |
| 1:50 | 可画垄，单垄只画分界不画瓦件断面 | 外轮廓与主要构件 | 可画单根 | 主要分缝 |
| 1:20 及更大 | 瓦件断面与搭接 | 各构件与分件关系 | 单根与望板 | 真实断面与榫卯 |

简化后的图元仍须引用源构件，`sourceEntityId` 覆盖率不因简化下降。简化规则写入制图配置，不写死在生成器分支里。

同一张图上出现两种细节层级时，用局部详图索引表达，不在同一视图内混用。

### 4.4 图面标注体系

标注根据对象、视图与尺寸依据产生，不以固定条数代替实际表达要求。

标注不得按视图套模板。此前每个视图固定产出三条标注（一条总宽尺寸、一条图名、一条资格声明），与建筑规模无关：712 条结构线的样本与十万条结构线的项目标注数量相同。这不是按尺寸链生成的体系，量化事实见 `文档/05_验证证据/12_图纸差距与一致性核对/README.md` 第三节。

标注由两层决定，各自可核对：

- 策略层规定哪类视图必备哪几种标注、每种的条数上限。写在 `packages/domain/src/drawing-annotation-policy.ts`，是数据不是分支。
- 规划层从项目事实与几何派生具体标注：哪条轴线、取自哪个构件、位置多少。写在 `packages/infrastructure/src/annotation-planner.ts`，随成果矩阵下发，制图侧只解析成图元。

必备标注种类按视图：

| 视图 | 必备 | 可选 |
|------|------|------|
| 平面 | 图名、图形总尺寸、资格声明、轴网、轴间尺寸链、北向 | 剖切索引、构件标注 |
| 立面 | 图名、图形总尺寸、资格声明、轴网、标高 | 构件标注 |
| 剖面 | 图名、图形总尺寸、资格声明、轴网、轴间尺寸链、标高 | 详图索引、构件标注 |
| 详图 | 图名、图形总尺寸、资格声明、构件标注 | 无 |
| 轴测 | 图名、资格声明 | 无 |

轴测不出尺寸：轴测是整体关系示意，标出的长度无法按图复核，标了反而误导。

四条硬要求：

1. **每条标注都能追到源。** 标注对象带 `sourceRefs`，指向具体构件或事实，检查时逐条解析，解析不出即为不合格。
2. **轴线只取位置有出处的构件。** 构件的位置来源记在几何契约的 `positionBasis`，与某条尺寸的来源是两回事。位置由生成器为几何完整性自行排布的构件不声明这一项，因此不参与定轴。把生成器的排布画成定位轴线，等于把排布显示成实测定位。
3. **轴线与标高带依据说明。** 有柱网的项目按柱心线，没有柱网的按实测墙心线，图上如实区分实测、图上量取、规则推算与照片估算。一组构件共同定的线取其中最弱的来源。
4. **标高优先取项目里写明的尺寸。** 几何算出的是构造面，图纸写明的才是那条标高，两者相差一个构造层厚度以内时采用写明值。相差过大说明模型与项目记录是两个数，两个数并列记录，不由制图侧选一个。

可辨间距同 4.3：相邻轴号圈在成图上中心间距不足 8 mm、构件引线标注按比例超出上限时，超出部分丢弃并计数，丢弃数进检查记录，不允许压线，也不允许静默截断。

### 4.5 参考图对应关系

参考图用于检查所声明对象的表达深度，资料未支持的构造不得据参考图补入。

| 参考特征 | 本项目最低验收 |
|----------|----------------|
| 照片与测绘图并置 | 证据查看器能从照片定位到图纸对象；交付包含照片索引 |
| 古建屋面和装饰完整 | 屋面曲线、瓦垄、屋脊、檐口和实际存在的饰件可辨 |
| 木构与门窗细节完整 | 柱梁枋、斗栱或承托、门窗分格和格心不是空白矩形 |
| 剖面展示真实构造 | 屋面、承重木构、楼地面、台基和基础关系来自同源剖切 |
| 多级尺寸和标高 | 轴网、开间、总尺寸、关键构件和主要标高可以复核 |
| 修缮说明和引线 | 说明关联对象、病害或构造，不是悬空文字 |
| 三维材质和构件层次 | 颜色只辅助识别；对象语义和构件关系不能依赖贴图 |

## 5. CAD 文件最低要求

DXF 必须是可继续编辑的工程文件，不是图像、单一块或大量无语义碎线。

- 模型空间按 1:1 和统一单位建立。
- 图纸空间包含正确图幅、图签、比例视口和打印样式。
- 重复构件使用块；门窗、斗栱或栏杆实例保留对象引用。
- 尺寸使用 `DIMENSION`，文字使用 `TEXT` 或 `MTEXT`，材料使用 `HATCH`，重复图元优先使用 `INSERT`。
- 图层至少区分轴线、剖切、轮廓、投影、隐藏、尺寸、文字、填充、现状、病害、拟修和图框。
- 中文字体不得替换成缺字字体；PDF 打印不得乱码、裁切或丢线。
- 任务要求指定的规范资格工具必须完成打开、审计、选择、编辑、保存、重开和打印，且原生对象、布局、视口和来源关系不丢失。
- 第二 CAD 工具只检查打开、查看、选择和打印兼容性。它保存的兼容副本不得覆盖规范成果，也不得作为规范 CAD 的资格证据。
- 反向解析后能恢复图层、图块、标注、布局、视口和对象来源关系。
- 结构对象、详图对象和原生 CAD 标注反向解析后仍能关联 `sourceEntityId` 与 `geometryRevisionId`。

对象数或线条数不是质量指标。通过标准是语义完整、关系正确、图面清楚和可继续编辑。

## 6. 自动检查与人工审核

### 6.1 自动检查

自动检查至少覆盖：

- 项目事实、三维、平面、立面和剖面之间的尺寸与对象一致性。
- 视图是否为空、是否越界、比例是否可读、文字和尺寸是否重叠。
- 图层、线型、线宽、字体、块、填充、标注、视口和打印设置。
- IFC、GLB、DXF、SVG 和 PDF 的解析、哈希、对象映射和来源引用。
- 必要构件和图种是否生成，或是否有可解释阻断。
- 未知、推断、演示和不具备正式资格的内容是否被清楚标记。
- IFC、GLB、DXF、SVG 和 PDF 引用同一 `geometryRevisionId`。
- 除图框和注释外，结构性图元的 `sourceEntityId` 覆盖率为 100%。
- 用独立几何程序重算剖切，核对构件集合、轮廓、轴网、开口、标高和关键尺寸。
- 每张图按 `DrawingRequirement` 检查图种、尺寸类别、标高类别、构件、说明、来源和阻断，不按图元总数判断质量。
- 独立验证器检查关键构件的截面、曲率、拓扑、连接、包围盒、关键点和尺寸，不接受只改 `representation` 名称的简化几何。
- 独立验证器按 `curveToleranceMm`、`maxChordErrorMm` 和视图容差重算曲线、投影与剖切。
- 每条结构线检查类别、`sourceEntityId`、遮挡和隐藏状态；未分类线、三角网内部边和遮挡错误必须为零。
- 详图检查 `derivationTransform`，确保结构性图元 100% 来自同一几何版本的构件投影、剖切或可重算展开。
- 扫描生成器输入、仓库和交付包，确保外部参照文件及其路径、哈希、块、曲线和派生图元未进入生成依赖。
- 300 dpi 成组渲染检查缺字、字体替换、问号占位、越框、裁切、重叠、异常留白和细线丢失。

对象数、图元数、文件大小和软件能否打开只作为诊断或兼容性证据，不得作为 L1、L2 或 L3 的通过条件。

### 6.2 人工审核

专业人员核对采用值，并承担以下专业工作：

1. 对资料无法唯一决定的构造、保护判断和高风险问题作专业决定。
2. 对成组三维与图纸预览进行最终专业复核。

审核人员不重复录入系统已经掌握的尺寸、身份和来源。修改意见应定位到对象、视图或说明，并重新检查受影响成果；影响关系不完整时须显示限制。

## 7. 验收门槛

制作任务通过只说明约定范围的结果成立，不能升级为未验证的专业能力。

### 7.1 当前制作案例

T-DL-01 按 V01 至 V04 检查，以下条件必须同时满足。

1. 从固定原资料与空项目开始，完成目标模型和三个视图，无隐藏参数包。
2. 原图明确标注的关键尺寸经单位换算后错误为 0；冲突和不可辨认项保留。
3. 模型、平面、立面和剖面采用同一几何版本，剖面由真实剖切产生。
4. DXF 按第 5 节完成打开、选择、编辑、保存、重开与打印。检查工具、版本和结果逐项记录；缺少工具时该项未完成。
5. PDF 无缺字、裁切、尺寸遮挡和越框；成图比例与图签一致。
6. 修改一个已核对尺寸后重新生成，相关模型与图纸采用新值，旧结果保留。
7. 未知构造、模拟数据、专业复核和签发状态明确。目标图纸缺失或质量未过则任务未通过。

### 7.2 后续专业样板与完整单体

专业样板需独立检查资料充分性、实际构造、曲面、节点、图面及责任边界。

L1 检查选定局部的完整构件关系、真实剖切、控制点、曲率与连接。L2 还需完成任务要求的单体图种。每项容差和预期对象在测试前冻结，由独立检查者核对，生成器不能自行授予等级。

中国古建适用性按 V06 执行。没有原始尺寸与专业复核时，当前结果只保留内部技术用途。L3 还需要真实身份、审核、授权和签名验证，不在当前本机实现范围内。

## 8. 标准与样本的使用限制

旧北京征求意见稿的条款表不再作为现行验收依据，正式标准适用性按日期与项目条件判断。

北京正式文本要求用于北京市已公布历史建筑的信息采集与数字化处理，自 2026-12-01 实施。当前样本不据此宣称合规，也不把北京市要求外推为全国古建规则。原草案中的图层命名与定价推论删除；项目图层仍按第 5 节的编辑与检查条件执行。

正式使用前需由项目专业负责人确认适用标准、成果范围与条款对应关系。未取得真实项目与负责人时，此项明确为尚未开展，不用内部演示签发替代。
