# 01 · 核心 PRD：古建保护成果工作台 v5.0

## 0. 项目任务摘要

本产品帮助古建测绘与文保勘察人员，把已有现场资料转成可编辑、可核对的模型与测绘图纸，减少资料转写、构件整理、建模和制图的人工工作。

**表 1：项目任务摘要**

| 项目 | 现行定义 |
|---|---|
| 第一用户 | 测绘或文保勘察团队中承担资料整理、建筑建模和图纸编制的专业人员 |
| 核心场景 | 现场资料已取得，需要根据照片、实测记录和历史图纸制作单栋建筑的模型与测绘图纸 |
| 主要价值 | 减少成果制作的人工操作和返工；来源、版本、历史和归档由系统辅助维护 |
| 当前阶段 | 形成经得起产品评审的可交互案例；真实用户试点、商业验证和正式交付尚未开展 |
| 当前输入 | 已有照片、实测表、带尺寸草图和历史图纸；本阶段不接入扫描硬件或建设点云自动重建能力 |
| 当前输出 | 资料支持范围内的构件化模型、平面、立面、剖面、可编辑 DXF、PDF 及必要说明 |
| 责任 | AI 提取候选并辅助修正；程序计算与生成文件；专业人员核对采用内容和成果质量 |
| 首页 | 建筑制作进展和待处理事项优先；项目管理作为辅助入口 |
| 主流程 | 创建任务与提供资料，生成可视预览，结合原件核对和修正，检查并导出 |
| 开工顺序 | 独立样板已完成；先验收正式文档，再实施产品代码；进度以路线图为准 |

专业人员提供已有资料，先查看资料支持的模型、图纸或对象预览，再结合原件核对和修正。系统复用已采用数据生成可编辑成果，自动维护必要来源与历史。实际价值按第 2.5 节的人工投入与质量指标验证。

**核心业务：**

1. 专业人员定义建筑任务并提供资料，系统展示可支持的预览和具体缺项。
2. 专业人员结合原件核对对象和尺寸，程序用采用数据生成同源模型和测绘图纸。
3. 专业人员修正成果，系统更新受影响内容并保留必要记录。
4. 专业人员导出可编辑文件和质量说明，系统附带来源与使用限制。

## 2. 需求背景

本轮优先检验已有资料能否更高效地转成成果，用户需求强度和节省工时尚未获得真实用户验证。

### 2.1 愿景

让古建测绘与文保勘察人员把时间用于现场信息和专业质量判断，减少资料转写、重复建模与制图工作。

### 2.2 目标用户

直接操作用户是成果编制人员，专业负责人负责复核，委托方接收输出。

**表 2：用户与验证状态**

| 角色 | 工作与产品关系 | 验证状态 |
|---|---|---|
| 成果编制人员 | 整理已有资料，制作与修正模型、图纸 | 第一用户已确认，真实使用行为未验证 |
| 项目负责人或专业复核人 | 判断资料采用范围，核对成果质量 | 责任角色已定义，正式身份与签发不在本阶段 |
| 委托方 | 接收文件及适用说明 | 当前不直接操作工作台 |
| 团队或所在单位 | 可能承担工具费用 | 买单方假设，需试点后验证 |

### 2.3 现状与问题

现有内部样本能够生成文件，但原始资料到成果的完整任务仍有输入和核对缺口。

- 资料处理：图纸尺寸可能错读，候选需要核对。
- 建模输入：TIFF 读取、原件核对和候选到制作输入的关联已接通；完整几何参数与成果覆盖仍需按固定任务验证。
- 成果修正：文件查看与导出已有内部验证，原始资料到可用成果的完整人工投入尚未测量。

**结果**：当前可展示完整成果，但不能报告真实项目的节省工时。

**根因**：已有验收主要检查文件、页面与记录是否完整，缺少同资料、同成果要求下的制作过程对照。依据见[演示项目定义](04_演示项目定义.md)及[制作验证与成本](05_模型成本与商业回报.md)。

### 2.4 行业趋势

扫描、数据处理、建模和制图是可分别验证的环节，新闻中的总耗时不能直接作为本产品指标。

极光新闻报道提供了成果制作效率的场景参考，但未公开完整操作、精度与计时范围。现场点云重建与本阶段的已有资料制作使用不同输入。相关来源和限制归入[AI 与制图能力边界](../06_研究底稿/01_AI与制图能力边界.md)，本产品不承诺单张照片恢复整栋建筑。

### 2.5 目标与价值

本阶段先证明可交互的制作过程成立，再以人工对照判断效率，所有阈值都是验收约定而非实测结果。

核心指标只保留两项：同质量下的人工操作总时长、目标成果质量通过情况。费用和等待作为成本分项记录。情景估算与计算过程见[制作验证与成本](05_模型成本与商业回报.md)第 3.3 节。

## 3. 业务流程

用户围绕制作成果操作，系统自动维护资料关联与必要历史，不增加独立的记录维护任务。

### 3.1 主流程与业务规则

每次制作先固定目标和资料范围，先生成支持范围的预览，再核对、修正和导出。

1. 首次任务必填任务名称、建筑名称、制作目的、目标成果与输出单位。当前目的为现状测绘，单位默认毫米且可见。比例、图幅和剖切设置在出图前确定。

   输出单位支持毫米、厘米、米，作用于可编辑 DXF 的模型坐标、长度标注及 IFC 单位和坐标。图纸明确说明长度单位，标高仍以米表达并注明。转换保持建筑物理尺寸、图幅和比例一致，保留可辨认的小数。改变单位后，原成果保留供查看，重新生成并检查后才符合本次要求。GLB 按格式规定使用米，内部采用尺寸继续使用毫米。

2. 数据来源与确认状态分别记录。人工确认不把推算值、演示值或资料转写值变成现场实测值。
3. 至少一份可读建筑资料即可开始处理。系统提取候选并呈现原图定位、对象列表或有依据的几何预览。几何条件不足时保留原图与对象，不补默认尺寸。
4. 待核对候选可进入明确标记的预览，核对后成果只采用用户已核对内容。冲突值不自动选定，缺项只影响相关对象或图种。用户可逐项或成组核对，成组处理绑定实际展示条目。
5. 同一组已确认数据供模型和图纸使用，不要求用户重复录入。
6. 技术检查、专业复核与正式签发分别表达。当前新建或修改项目不得在本机正式签发。
7. 修改保留旧成果，重新生成采用新数据；影响范围不完整时明确显示限制。
8. 导出包含可编辑成果、必要说明和来源；成果包回导保留数据关系。
9. 单个文件读取或对象生成失败时，其余可读资料和支持部分继续处理。作业失败保留输入和旧结果，提供重试；展示本次实际结果。
10. AI 用量由真实调用记录产生，被动浏览不调用模型。具体确认机制见[界面与交互形态](03_界面与交互形态.md)第七节。

- P0：作为成果编制人员，我提供已有资料并查看可视预览，以便直接定位需要核对的对象。
- P0：作为成果编制人员，我结合原件核对尺寸与构件，以便减少重复转写和建模。

### 3.3 任务与对象数据

建筑、构件、尺寸、资料和成果分别编号，名称变更与重新生成保持对象身份。

**表 7：业务数据要求**

| 对象 | 必需信息 | 可补充信息 | 来源与更新规则 |
|---|---|---|---|
| 制作任务 | 名称、建筑、目的、目标成果、输出单位、状态 | 项目或村落、任务模板、负责人 | 用户设置；模板为可修改初始选择，当前仅现状测绘；内部编号自动生成 |

| 原始资料 | 文件、名称、类型、读取状态、对应建筑 | 记录时期、用途、对象位置 | 原件保留；派生图可定位回原图；相同文件可覆盖多项要求 |

| 位置与几何 | 原点、轴向、单位和参数的依据 | 标高基准、局部坐标、尺寸引用 | 原图区域和三维坐标分别记录；二维框选不直接成为三维位置 |

### 3.4 资料要求与成果预期

资料按必需、建议、额外补充分层，覆盖状态随目标成果和新增资料更新。

**表 9：资料三层要求**

| 层级 | 资料 | 覆盖内容 |
|---|---|---|
| 必需 | 平面或可读草图、尺寸记录或带尺寸图纸 | 对象范围、尺度与主体位置；同一文件可同时覆盖 |
| 必需，选择立面 | 对应方向立面或可校准照片 | 方向、尺度和所选立面的表达依据 |
| 必需，选择剖面 | 指定剖面或构造记录 | 剖切位置、楼层、所需高度与厚度 |
| 建议 | 其他方向照片、历史图纸与说明 | 核对视图关系、记录时期和来源冲突 |
| 额外补充 | 详图、节点照片、局部尺寸 | 增加有依据的局部表达 |

“必需”表示完成所选成果的资料要求。首次预览只需一份可读资料；缺少立面资料时，仍可查看已有平面对象与缺项。增加资料后重新提取并更新预览，用户继续核对新增或变化的内容。

资料覆盖由用户对照原件登记，记录本建筑的平面、尺度、高度、指定立面或指定剖面依据及页码、方向、标注或剖切位置。同一文件可支持多项内容；覆盖按内容统计，资料层级表示准备顺序。文件可读及上传成功均不自动表示覆盖完成。最新登记为空、资料失效或不可读时显示缺项；修改目标后重新计算所需依据。覆盖记录支持资料准备，具体尺寸、构件和成果仍按各自流程核对。

### 3.5 异常与恢复

异常处理保留任务和已有结果，并提供能够继续工作的入口。

**表 10：异常出口**

| 触发 | 处理与反馈 | 继续条件 |
|---|---|---|
| 必填字段或目标成果为空 | 字段旁说明缺项，保留已填内容 | 补齐字段 |
| 文件不支持或读取失败 | 逐文件说明，提供替换或移除；其他可读文件继续 | 至少一份可读资料 |
| 全部文件不可读或提取为空 | 保留原件，说明未取得可用对象 | 换文件、补充资料或重试 |
| 尺寸或位置缺失 | 在对象和相关图种标记所缺依据 | 补依据；可继续查看已有内容 |
| 来源冲突或错读 | 并列原文与候选，不自动采用；可修正或驳回 | 用户完成相关核对 |
| 模型、AI 或制图失败 | 显示具体失败，保留旧结果和输入；不重复创建有效成果 | 修正后重试，或继续可用操作 |
| 修改已核对数据 | 标出受影响内容，新成果重新检查 | 重新生成和检查 |
| 未保存离开 | 提供继续编辑、保存后返回 | 选择后执行，保存失败留在原页 |
| 范围超出当前支持 | 列出具体对象或图种及缺少条件 | 明确调整任务或补资料；不改写原失败记录 |

长度须为正值，相对标高允许零和负值；相对标高不作为构件长度引用。新候选缺类型时由核对人员明确选择，旧正长度记录保留原义。整体被驳回或替代的候选不再提供当前采用值，已有采用事实留作历史。

预览由候选、来源及最新核对记录只读计算。合法图上区域可叠加，缺失或越界保留文字位置，并支持临时原图框选；临时定位不写入尺寸事实。核对清单导出保留原文、候选、最新值、类型、状态和来源说明，生成后可保存文件或复制内容。

## 4. 功能规划

本阶段保留四个模块，制作能力优先，项目记录在后台支持全过程。

### 4.1 版本规划

版本顺序为制作案例、真实使用验证和正式部署。

**表 5：阶段目标**

| 阶段 | 完成定义 |
|---|---|
| 当前制作案例 | 文档一致；V01 至 V04 通过；展示输入、操作、输出和失败边界 |
| 真实使用验证 | 取得合格样本与参与者，开展 V05 至 V08，不预填收益 |
| 正式部署 | 根据试点结论决定组织权限、真实身份和正式签发，不纳入当前验收 |

### 4.2 功能架构

M1 负责资料输入，M2 负责建筑建模，M3 负责图纸制作与检查，M4 负责文件导出和辅助记录。

来源、版本和调用记录由系统自动保存，仅在用户需要核对、恢复或判断费用时展开。

### 4.3 功能清单

沿用 F01 至 F18 编号，现有页面名称保留，普通输入能力包含在原功能范围内。P0 为完成制作案例所需能力，P1 为后续核对便利，P2 为跨项目扩展。

| F08 | 跨项目构件复用 | 构件清单 | P2 | 新项目重新核对适用性与来源 |

### 4.4 需求范围

当前范围以已有资料制作单栋建筑的受限成果为界，不承诺任意建筑的自动重建。

- 必须完成：任务进展、普通资料输入、可视预览、原件核对、数据复用、模型与图纸生成、修正、检查和导出。
- 保留辅助：必要来源、状态、版本、修改历史、项目包和调用用量。
- 后续评估：跨项目构件库、独立档案平台、多人协作与正式签发。
- 本阶段不做：扫描设备接入、原始点云自动重建、缺资料的全建筑推断、修缮设计与结构安全结论。

专业质量以[质量基准](../02_技术/03_专业制图与建模质量基准.md)中与本次成果范围相关的条款为准。资料不足时缩小成果范围，不以补造数据满足完整图种要求。
