# 05 · 制作验证与模型成本 v1.1

## 1. 结论

当前没有完整人工基线、真实用户独立试用或付费证据，不能报告项目提效比例、单栋总成本或已验证价格。

模型调用只是制作成本的一部分。人工转写、资料准备、核对、修正、等待、制图计算与失败重试都应记录。验证编号与通过条件以[核心 PRD](01_核心PRD.md)第 2.5 节为准，任务输入见[演示项目定义](04_演示项目定义.md)第 3 节。

## 3. 人工投入对照

V05 对比同一输入、同一成果要求与同一质量门槛下的人工制作和产品制作。

### 3.1 对照方法

完整制作对照在 T-DL-01 资料条件满足后开展。T-DL-03 可先对照尺寸核对环节，用时不外推为整栋制作收益。开始前冻结原资料、任务书和核对表。

先记录操作者、相关经验、人工方法和所用软件版本。人工组可用操作者通常使用的 CAD 工具，但不能导入本产品生成结果。产品组从空项目开始，不能加载完成包或隐藏参数。两组都不得读取对方的过程文件。

每组至少完成一次全程记录。内部操作者熟悉资料会产生练习影响，因此内部结果仅用于定位制作负担。真实试点优先使用经验相近的不同参与者，并交换任务顺序；报告仍需说明样本数量与限制，不从少量任务外推行业收益。

### 3.2 计时与质量

人工用时以实际操作时间累计，等待时间和总历时另外报告。

**表 2：每次运行的必填记录**

| 字段 | 记录要求 |
|---|---|
| 任务与输入 | 任务编号、文件哈希、成果要求、预期核对项 |
| 人员与环境 | 操作者、经验、工具版本、模型名称及配置 |
| 人工时间 | 资料准备、转写、核对、建模、制图、修正、导出分别计时 |
| 等待与中断 | 模型及制图等待、网络失败、休息与外部中断分别记录 |
| 人工干预 | 重复录入次数、开发者代操作、额外脚本和隐藏输入 |
| 质量与结果 | 目标文件、关键尺寸错误、未完成项、返工次数、V01 至 V04 结果 |
| 调用与计算 | 每次调用状态和实际计费用量、制图计算时间、已知服务费用 |

人工节省比例按“人工组操作总时长减产品组操作总时长，再除以人工组操作总时长”计算。产品组质量未达到同一门槛时，不计算提效结论。只完成部分任务时报告部分任务用时，不能当作整栋建筑制作收益。

V05 通过要求质量不下降且人工操作总时长减少。未通过时按时间分项定位原因，修正后另记一次完整测试，保留原失败记录。

### 3.3 两项指标与情景估算

人工操作总时长与目标成果质量共同决定价值，模型等待和费用作为补充成本分项。

**表 5：用于评审的指标**

| 指标 | 计算与通过条件 | 当前状态 |
|---|---|---|
| 同质量人工操作总时长 | 汇总准备、转写、核对、建模、制图、修正、导出；产品组少于人工组且质量达到同一门槛 | 完整对照未开展 |
| 目标成果质量通过情况 | 检查固定目标的关键尺寸、模型图纸一致性、编辑性和未完成项；全部达到 V03 才通过 | T-DL-01 资料预检未通过 |

**表 6：情景估算的假设输入，单位为分钟**

| 环节 | 人工组假设 | 产品组假设 |
|---|---:|---:|
| 资料准备与转写 | 120 | 60 |
| 核对 | 60 | 90 |
| 建模与制图 | 240 | 60 |
| 修正、检查与导出 | 60 | 30 |
| 人工操作合计 | 480 | 240 |

数值为本轮计算示例，没有来自实际任务的工时证据。假设产品减少转写和建模，但增加预览核对时间；两组同一目标和质量都通过。按这些假设，节省 240 分钟，比例为 50%（基数为人工组 480 分钟）。若产品组核对增加 120 分钟，则合计 360 分钟，比例降为 25%。

验证方式是按第 3.1、3.2 节计时，将示例全部替换为同任务实际记录。如果质量未通过，计算示例不能作为提效结论。导师课堂中的人日和人数用于解释价值表达，不作为本项目数据。

## 4. 模型与运行费用

费用按真实账单或可核对的计费用量计算，不用固定单次均价替代实际任务成本。

一次调用费用等于各类计费用量乘对应单位价格之和。缓存输入、普通输入和输出分别计算；失败调用是否计费以服务商账单为准。未知费用显示“未取得”，不能记为 0 元。

一次制作任务总成本包含模型调用、计算与存储、人工准备和返工。各项缺少数据时分别留空并说明来源，不能仅用模型费命名为总成本。

**表 3：预算与服务状态**

| 事项 | 当前状态 | 使用规则 |
|---|---|---|
| 模型与接口 | 当前工程接入 Kimi；具体配置以运行记录为准 | 更换模型后在同一任务上重新测量质量和用量 |
| 模型单价 | 代码中保留带日期的历史价格 | 每次预算前核对官方当日价格；历史价格仅用于重算旧记录 |
| 单任务预算 | 未建立完整基线 | 用真实运行汇总，不承诺单栋成本上限 |
| 免费额度与售价 | 未决定 | V08 后结合运行成本与采购条件决定 |
| 数据传输与部署 | 当前仅使用获准资料开展内部验证 | 境内服务商不自动证明数据传输合规；真实项目按资料授权和部署条件另行核对 |

AI 不可用时显示失败并保留项目，允许继续不依赖模型的操作。不得用关键词回答或预置建议冒充本次模型输出。确定性建模、制图的计算消耗与模型调用分别展示。

## 5. 真实用户与付费验证

V07、V08 必须由真实参与者提供证据，内部代理试用不满足条件。

**表 4：外部验证的执行条件**

| 编号 | 所需参与者与资料 | 必须记录 | 当前状态 |
|---|---|---|---|
| V06 | 中国古建资料及目标专业人员；样本条件见演示项目定义第 3.4 节 | 实测依据、构件适用范围、图面核对和未支持部分 | 未开展 |
| V07 | 至少一名未参与开发的目标成果编制人员 | 独立任务过程、中断、求助、开发者代操作和产出质量 | 未开展；需取得参与者 |
| V08 | 完成实际试用的使用者与具有采购决策职责的人员 | 使用频率、现有工具、可接受价格或预算、采购前提与明确意向 | 未开展；需先完成实际试用 |

一名参与者只能提供个案结论。V08 中表达兴趣不等于付费承诺；没有预算或明确购买条件时，记录为需求反馈，付费假设保持未验证。

验证记录随对应实施单元保存。任何文档不得将“尚未取得”改写成已通过，也不得以取消验证项消除资料或用户缺口。
