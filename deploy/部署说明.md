# 公网展示部署说明 v1.0

线上应用部署在 `heritage.jiajiajiang.com`，前端、后端、AI 与 CAD 功能均由同一台服务器提供。

目标环境是腾讯云上海轻量应用服务器，配置为 4 核、4 GB 内存，操作系统为 OpenCloudOS，公网 IP 为 `49.235.158.54`。域名 `jiajiajiang.com` 已备案。

Nginx 提供 HTTPS 和静态前端。`/api` 反向代理到本机 Node 服务，Node 服务按需启动 Python CAD 进程。Kimi 密钥只保存在服务器的 `/etc/gujian/server.env`。

## 一次性开通步骤

一次性开通需要完成域名解析、证书、防火墙、服务安装和密钥配置。

1. 在 `jiajiajiang.com` 的 DNS 解析中增加 A 记录。主机记录为 `heritage`，记录值为 `49.235.158.54`。
2. 在腾讯云控制台申请 `heritage.jiajiajiang.com` 的免费 SSL 证书。签发后下载 Nginx 格式证书，并把两个文件放入服务器的 `/etc/nginx/certs/`。
3. 在轻量应用服务器防火墙中放行 TCP 80 和 443 端口。
4. 服务器上以 root 执行 `deploy/setup-server.sh`（代码用 rsync 推上去时先 `export GUJIAN_SKIP_CLONE=1`）。
5. 编辑 `/etc/gujian/server.env` 并填写 `KIMI_API_KEY`，然后执行 `systemctl restart gujian-server`。

## 日常更新

日常更新采用独立候选构建、保留旧版本、切换入口的方式，测试通过后再上线。

只打包运行源码、依赖清单与已授权公开的演示资源，不同步整个工作区。前后端和 Python 代码应作为同一候选验证；演示数据变化时重新构建演示包。当前 `/opt/gujian/app` 为符号链接，后续更新应建立新的发布目录，不能直接覆盖旧备份或运行数据。

2026-10-10 发布目录为 `/opt/gujian/releases/style-20261010-020932`，`source` 是当前代码，`previous-app` 保存旧版本以及被新版本引用的 `.data` 与 `.venv`。密钥仍在 `/etc/gujian/server.env`，Nginx 与 systemd 配置未改动。目录内保存构建记录、文件哈希、公开接口检查和恢复说明。

本次版本需要恢复时，在服务器执行：

```bash
bash /opt/gujian/releases/style-20261010-020932/style-release-switch.sh rollback
```

脚本恢复旧入口并检查服务，保留运行数据。该脚本针对本次切换，下一次发布需使用新的候选与备份路径。

## 公网防护

公网模式由 `GUJIAN_PUBLIC_HOST` 启用。服务端只允许指定域名，会话 Cookie 使用 Secure 属性。

助手对话和生成作业分别计数，并同时设置单 IP 与全站每日限额。额度用完后，接口返回 HTTP 429 和中文说明。计数在东八区每日零点清零。默认额度和可配置项见 `server.env.example`。

## 已知限制

当前部署适合公开产品展示，不满足多人生产环境的可用性要求。

- 单机单进程：CAD 作业并发为 1，第二个访客的生成请求会排队。
- 限额计数在进程内存里，重启服务当日计数清零（展示场景可接受）。
- 更新演示包后需要重新执行 rsync。已有访问者还需要在项目列表选择“更新演示项目”。
