# 产品界面设计

## 目标

界面设计应让目标用户理解当前任务、核对依据、完成操作并处理异常。视觉质量、任务效率和专业信息完整性同时通过验收。

## 使用顺序

1. 读取 `pm-context` 指向的现行 PRD、用户旅程、界面结构和视觉规范。
2. 检查用户、任务、输入、结果和验收目标是否完整。缺口返回产品经理。
3. 用真实演示内容梳理页面对象、状态、操作和信息优先级。
4. 先设计一条关键任务流程及其代表页面；未改变产品边界时直接扩展到同类页面。
5. 将重复规则收敛为设计令牌、基础组件和页面模式。
6. 交付界面方案、交互说明和必要状态，供架构与实施使用。
7. 实施后检查真实页面，记录设计差异、影响和处理结论。

## 最小产出

按任务范围选择产出，不为单页修改建立完整设计项目。

| 任务 | 必要产出 |
|---|---|
| 调整单个页面 | 页面目标、信息层级、关键状态、修改说明 |
| 新增一条流程 | 任务流程、代表页面、异常与恢复方式 |
| 重做工作台 | 信息架构、关键流程、代表性高保真页面、组件与状态规范、实施验收清单 |
| 审查实现 | 页面截图或实际界面、差异清单、严重程度、处理建议 |

## 设计判断

- 先展示完成当前任务所需的信息，再展示补充信息。
- 主操作随任务状态变化，同一任务环境只保留一个最高权重操作。
- 数据与证据保持可见关联，选中对象后能够定位其来源。
- 风险、资格和责任信息按后果确定层级，不作为装饰标签处理。
- 长时间桌面作业优先保证可读性、稳定布局和键盘可达。
- 外部产品只提供布局、交互或视觉原则参考，不直接复制页面结构。

## 交付检查

- 页面名称、字段和状态与现行产品文档一致。
- 正常、空白、加载、失败、阻断、确认和恢复状态按实际任务覆盖。
- 代表页面使用真实字段、真实文本长度和目标数据量。
- 组件包含默认、悬停、聚焦、禁用、加载和错误状态中适用的部分。
- 1280 px 宽度下关键任务可完成，窄窗口的收起顺序符合视觉规范。
- 实施角色无需补充信息层级、操作顺序或状态反馈。
- 验收同时检查静态截图与连续操作过程。

## 边界

- 产品范围与优先级由产品经理确认。
- 古建术语、证据等级和责任边界由古建领域审阅者核对。
- 数据结构、接口和框架由技术架构师决定。
- 视觉规范服务于用户任务。现行页面证明规范存在问题时，记录问题并提出修订，不让实现同时遵循互相冲突的规则。
