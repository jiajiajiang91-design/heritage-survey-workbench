# 写实施单元

## 目标

执行方读取固定开工入口和当前单元三件套后即可实施，详细文档按引用加载。

## 使用顺序

1. 读取核心 PRD 第 0 节、技术架构第 0 节、路线图当前阶段行，以及 PRD 中本单元对应的功能条目。
2. 核对产品边界、工程约束、阶段依赖和验收目标。只有缺口触发 `pm-context` 确认门槛时提问，其余信息按权威文档处理。
3. 按 `templates/` 下三份模板写规格、计划、验收，放进 `文档/04_实施单元/{编号}_{单元名}/`。
4. 复述测试：执行方只凭固定入口与三件套说明任务和完成条件，缺失内容补回文件。
5. 实施。每完成一个任务组跑该组的验证，不攒到最后。
6. 收口：跑 `.claude/skills/quality-check/scripts/run-all.mjs --full`，必须修复项清零。
7. 按 `references/复盘清单.md` 复盘。验收全部通过且未触发确认门槛时，直接更新路线图状态并关闭单元。

## 必填与可选

小单元只写必填节，跨会话的大单元写全。模板中标注了每节的适用条件，不适用的连标题一起删，不留空节。

| 文件 | 必填 | 可选 |
|---|---|---|
| 规格 | 依据、范围、不做 | 用户故事、业务规则、界面要求、数据约束、非功能要求 |
| 计划 | 目标、任务组、完成定义 | 风险 |
| 验收 | 验收条件、自动检查、复查清单、结论 | 人工检查步骤 |

## 边界

- 规格只引用核心 PRD 的功能编号，不新设需求。发现 PRD 缺内容时回去改 PRD。
- 验收条件在开工前写定。事后补写的条件不构成验收。
- 实施中发现规格与代码现状冲突，先停下说明，不在代码里绕开规格另做一套，也不改规格迁就实现。
- 证据仍归 `文档/05_验证证据/`，单元内只留指针。
