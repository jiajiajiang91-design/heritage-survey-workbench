# 技术架构

## 进入条件

PRD 的目标用户、核心场景、版本范围、输入输出、业务规则、人工责任、功能清单、异常流程和验收标准全部确认后才进入。缺任一项时列出问题退回产品环节，不用技术方案补产品空白。

## 使用方式

按 `references/技术架构工作法.md` 的分析顺序执行：现状盘点、问题定位、约束确认、方案比较、架构定义、交叉检查、任务拆分。

## 边界

- 架构由本环节产出，不写进 PRD。PRD 只给目的与验收标准。
- 架构环节只形成方案，代码修改进入实施单元。方案触发 `.claude/context/pm-context.md` 的确认门槛时暂停，其余方案直接拆为实施单元。
- 每项任务可独立完成、验证、中断恢复和回退。
